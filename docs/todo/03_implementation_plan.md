# TODOアプリ 実装計画書 (03_implementation_plan.md)

## 工程1: SQLファイルをGitに保存する

* **対象ファイル**: `sql/todo/020_create_todo_tasks.sql`
* **作業内容**:
* `sql/todo/` ディレクトリ内に、タスクテーブル作成用のDDLファイルを作成する。
* 以下のSQLを記述し、Gitにコミットする。
```sql
CREATE TABLE IF NOT EXISTS todos (
    id SERIAL PRIMARY KEY,
    title VARCHAR(100) NOT NULL,
    completed BOOLEAN DEFAULT FALSE NOT NULL,
    created_at TIMESTAMP WITH TIME ZONE DEFAULT CURRENT_TIMESTAMP
);

```




* **確認コマンド**: `git status` および `git log -n 1`
* **期待結果**: `sql/todo/020_create_todo_tasks.sql` がGitの管理下に追加されていること。
* **失敗時に最初に見る場所**: ファイルパスの記述ミス、Gitのステージング状態。

---

## 工程2: Neon SQL Editorでテーブル作成SQLを手動実行する

* **対象ファイル**: なし（Neonダッシュボード上の操作）
* **作業内容**:
* Neon PostgreSQLのコンソール（SQL Editor）にログインする。
* 工程1で作成した `sql/todo/020_create_todo_tasks.sql` の中身を貼り付けて実行し、`todos` テーブルを作成する。


* **確認コマンド**: SQL Editor上で `SELECT * FROM todos;` を実行する（または後続のDB接続確認）。
* **期待結果**: エラーなくクエリが実行され、空の `todos` テーブルが存在することが確認できること。
* **失敗時に最初に見る場所**: `DATABASE_URL` の接続先データベースの誤り、SQL構文エラー。

---

## 工程3: バックエンドモデルの実装

* **対象ファイル**: `src/apps/todo/todoModel.ts`
* **作業内容**:
* 既存の `db.ts` をインポートし、データベースに対するCRUD操作（全件取得、登録、完了状態更新、削除）を行う関数を実装する。


* **確認コマンド**: `npx tsc --noEmit` （型エラーがないことの確認）
* **期待結果**: TypeScriptのコンパイルエラーが発生しないこと。
* **失敗時に最初に見る場所**: `db.ts` からエクスポートされている型や関数のシグネチャ、インポートパス。

---

## 工程4: バックエンドコントローラーの実装

* **対象ファイル**: `src/apps/todo/todoController.ts`
* **作業内容**:
* リクエストを受け取り、バリデーション（ `title` の空白除去、1〜100文字チェック、`id` の数値チェック等）を行い、`todoModel` を呼び出して適切なHTTPステータスコードとJSONレスポンスを返すハンドラー関数群を実装する。


* **確認コマンド**: `npx tsc --noEmit`
* **期待結果**: コンパイルエラーがなく、各API仕様（REQ-01〜04）に沿ったエラーハンドリングやデータ返却のロジックが記述されていること。
* **失敗時に最初に見る場所**: リクエストボディやパラメータの型定義、バリデーションロジック。

---

## 工程5: バックエンドルーターの実装

* **対象ファイル**: `src/apps/todo/todoRouter.ts`
* **作業内容**:
* Expressの `Router` を用いて、各エンドポイント（GET、POST、PATCH、DELETE）と `todoController` の関数をマッピングするルーティング定義を行う。


* **確認コマンド**: `npx tsc --noEmit`
* **期待結果**: ルーターが正しく定義され、エラーなくコンパイルできること。
* **失敗時に最初に見る場所**: コントローラー関数のインポートパス、Expressのルーティング構文。

---

## 工程6: `index.ts` への `todoRouter` の最小限の登録

* **対象ファイル**: `index.ts`
* **作業内容**:
* 既存の `/` や `/api/db-check` のコードを変更・破壊しないように配慮しつつ、ファイル上部に `todoRouter` をインポートし、`app.use('/api/todo/v1', todoRouter)` およびビュー用のルーティング（例: `app.get('/todo', ...)`）を追加する。


* **確認コマンド**: `npm run dev` （またはビルドコマンド）
* **期待結果**: サーバーが正常に起動し、既存のエンドポイントおよび新設のエンドポイントがルーティングに登録されること。
* **失敗時に最初に見る場所**: `index.ts` のインポート文、ルーターのマウントパスの記述ミス。

---

## 工程7: ビュー（EJS）の作成

* **対象ファイル**: `views/todo/index.ejs`
* **作業内容**:
* TODO画面用のEJSテンプレートを作成する。
* タスク入力フォーム、タスク一覧を表示するコンテナ、およびブラウザ用スクリプト（ `/todo/todo.js` ）の読み込みタグを配置する。


* **確認コマンド**: ブラウザで `http://localhost:3000/todo` にアクセスする。
* **期待結果**: EJSが正常に描画され、HTML画面が表示されること。
* **失敗時に最初に見る場所**: ビューエンジンの設定、EJSファイルの配置パス、テンプレート内の構文エラー。

---

## 工程8: クライアントサイドJavaScriptの実装

* **対象ファイル**: `public/todo/todo.js`
* **作業内容**:
* `TodoApi` クラス（またはそれに相当するAPI通信モジュール）を実装し、Fetch APIを用いてバックエンドの各エンドポイント（GET、POST、PATCH、DELETE）と通信する処理を記述する。
* フォーム送信やチェックボックス変更、削除ボタン押下時のイベントリスナーとDOMの動的更新処理を実装する。


* **確認コマンド**: ブラウザのDeveloper Tools（Console / Networkタブ）を開いて `/todo` にアクセス・操作する。
* **期待結果**: 画面からの操作に応じてAPIリクエストが正しく飛び、エラーなく画面が即時更新されること。
* **失敗時に最初に見る場所**: ブラウザの開発者コンソールのJavaScriptエラー、FetchのURLパスやリクエストボディの構造。

---

## 工程9: 総合動作確認

* **対象ファイル**: 該当なし（結合テスト・動作確認）
* **作業内容**:
1. ローカル環境で一連の操作（一覧表示、タスク追加、完了切替、削除）が意図通りに動作することを確認する。
2. Vercelへのデプロイを行い、Preview/Production環境でもNeon DBを経由して同様に動作することを確認する。


* **確認コマンド**: ローカルでの動作確認、およびデプロイ先URLでのブラウザ確認。
* **期待結果**: すべての要件（REQ-01〜04）を満たし、エラー時に適切なHTTPステータスが返ること。
* **失敗時に最初に見る場所**: 環境変数（`DATABASE_URL`）の設定状況、Vercelのデプロイログ・サーバーログ。
