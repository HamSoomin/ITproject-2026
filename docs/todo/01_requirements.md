# TODOアプリ 要件定義書 (01_requirements.md)

## 1. 目的・対象範囲

本ドキュメントは、Express + TypeScript + EJSで構築された既存のWebサイトに対し、新たに「TODO機能」を追加するための要件を定義するものです。

* **対象範囲**:
* 画面は `/todo` に配置する（既存の `/` および `/api/db-check` はそのまま維持する）。
* バックエンドでは既存のDB接続および `DATABASE_URL` を利用する。
* データベースは学生自身のNeon PostgreSQLを使用し、Preview環境とProduction環境は同じNeon DBを参照する。
* 個人情報は扱わず、架空のデータのみを使用する。
* V1におけるスコープ外：ユーザー認証、優先度設定、タスクの絞り込み機能、タイトルの更新機能。



---

## 2. 4機能と受け入れ条件

REST APIは `/api/todo/v1/todos` をエンドポイントとし、GET、POST、PATCH、DELETEの4操作を対象とします。

### REQ-01: タスク一覧取得

* **操作**: `GET /api/todo/v1/todos`
* **入力**: なし
* **結果**: 登録されているすべてのタスク一覧をJSON形式で返却する。タスクが0件の場合はステータスコード `200` と `data: []` を返す。
* **エラー**: 500 (サーバーエラー) など
* **受け入れ条件**:
* データベース上の全タスクが配列として取得できること。
* 件数が0件の場合でもエラーにならず、`200 OK` で空の配列が返ること。


* **確認方法**: ブラウザから `/todo` にアクセス、またはAPIクライアント等でリクエストを送り、一覧が正しく表示・取得されることを確認する。

### REQ-02: タスク登録

* **操作**: `POST /api/todo/v1/todos`
* **入力**: JSONボディ (`{ "title": "タスク名" }`)
* **結果**: 新規タスクを作成し、作成されたタスクデータを返却する。ステータスコードは `201 Created`。
* **エラー**: 400 (不正なリクエスト)、422 (バリデーションエラー)、500 (サーバーエラー)
* **受け入れ条件**:
* `title` は前後の空白を除いて 1〜100文字 であること。
* 空白のみのタイトルや、100文字を超える場合はエラーとなること。


* **確認方法**: 画面の入力フォームからタスクを追加し、一覧に即時反映されることを確認する。

### REQ-03: 完了状態の部分更新

* **操作**: `PATCH /api/todo/v1/todos/:id`
* **入力**: URLパラメータ (`id`: 1以上の整数) および JSONボディ (`{ "completed": true/false }`)
* **結果**: 指定したタスクの完了状態 (`completed`) を更新し、更新後のデータを返却する。
* **エラー**: 400 (不正なID)、404 (タスクが存在しない)、422 (バリデーションエラー)、500 (サーバーエラー)
* **受け入れ条件**:
* 指定したIDのタスクの `completed` ステータスが切り替わること。
* 存在しないIDを指定した場合は404エラーになること。


* **確認方法**: 画面上のチェックボックスをクリックし、完了状態が切り替わり永続化されることを確認する。

### REQ-04: タスク削除

* **操作**: `DELETE /api/todo/v1/todos/:id`
* **入力**: URLパラメータ (`id`: 1以上の整数)
* **結果**: 指定したタスクを削除する。成功時はステータスコード `204 No Content` を返し、レスポンスボディはなし。
* **エラー**: 400 (不正なID)、404 (タスクが存在しない)、500 (サーバーエラー)
* **受け入れ条件**:
* 指定したIDのタスクがデータベースから削除されること。
* 削除成功時にレスポンスボディが空（204）であること。


* **確認方法**: 画面上の削除ボタンを押し、対象のタスクが一覧から消えることを確認する。

## 3. 共通のデータ・エラー条件

* **成功時のレスポンス形式**:
* 原則として、データを含む場合は `data` プロパティを持つJSONオブジェクトとして返却する（一覧・登録・更新時）。


* **エラーコードの定義**:
* `400 Bad Request`: リクエストの形式が不正な場合。
* `422 Unprocessable Entity`: バリデーションエラー（例: タイトルの文字数オーバー、必須項目の欠落など）。
* `404 Not Found`: 指定したIDのタスクが存在しない場合。
* `500 Internal Server Error`: 予期せぬサーバー内部エラーが発生した場合。
* `503 Service Unavailable`: データベース接続エラーなど、サービスが一時的に利用できない場合。

## 4. 環境別確認

* **開発 (Local) 環境**:
* ローカルのExpressサーバーおよびNeon DB接続を確認し、正しくCRUD操作が行えることを確認する。


* **Vercel (Preview / Production) 環境**:
* デプロイ先においても、環境変数 `DATABASE_URL` を用いて同一のNeon DBへ正常に接続できること。
* ブラウザから各API（Fetch経由）および画面描画が問題なく動作することを確認する。
